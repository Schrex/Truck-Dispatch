# How it works today

What the app does as built, page by page. Words in capitals are defined in [`GLOSSARY.md`](../GLOSSARY.md); the API behind each action is in [`api.md`](api.md). It is a standalone Cloudflare Worker backed by D1 with **synthetic** Drivers, Trucks, Jobs, Places, Materials and Foremen only, plus the Inspection checklist's starting items (reference data). Inspections made on it are kept (append-only). Hub integration (at `/truck-dispatch/`), sign-in and production are later phases ([roadmap](specs/roadmap.md)).

## Dispatch board (`/`)

### Lanes
- Opens on the next **Working day** (US Eastern; on a Friday, Monday).
- One lane per Driver (his initials in a yellow circle, name and usual Truck), and an Unassigned lane last. A removed Driver has a lane only on a day he has work: his initials greyed, "Removed · …" before his Truck line, and no **+**. A lane with no Assignments says "Nothing planned yet".
- **Check-ins (today only):** when the day on screen is today, each Driver's lane shows his check-in in place of his usual Truck: "Truck 24 · checked in 6:42" (his latest Inspection; US Eastern, 24-hour clock), adding "· needs repair" when that Inspection had a Needs repair item, or "Not checked in" until he has. Two Drivers checked in to one Truck both show it. The Board reads the check-ins again when the page regains the focus; if they cannot be read, the lanes show the usual Truck. On any other day the lanes show the usual Truck as before.
- **Open Truck problems (today only):** on today a lane gets a red mark beside its Truck line when the Driver's Truck has an open Truck problem: the Truck he checked in to, or his usual Truck before he checks in. Hovering the mark shows the problems' notes; tapping it lists them under the line (tapping again puts them away). The Board reads the open problems again when the page regains the focus, so one marked fixed in Settings loses its mark; if they cannot be read, the marks stay as they were. No lane mark on any other day.
- Each lane shows that day's **Assignments** as blocks in order, reading "From → To" (or the note), marked First (the first that is not cancelled) and Then.
- Every block starts with a **kind pill** beside First or Then: a black **HAUL** pill, or a blue **MOVE** pill. A Move block reads its machine in bold, then "Wintergarden → BK" (the note and Truck follow). The pill only says the kind: the outline and the marks keep their state colours (dashed Draft, Changed, Added, Cancelled), so a Changed Move is marked Changed like any other.
- A Haul block leads with its **For** in bold, "For Brody", followed by a light grey **Customer** tag when For is a Customer ("For Jaus · Customer"); with For blank it reads as below. With an **At**, the line under For reads like Dave's message, showing only the parts that are set: "at Cobblestone · CR2", "at TIUNY · Asphalt · → Villager" (the note and Truck follow). With For set and no At, From or To, it says "No place yet" in grey. It also shows the Truck: one the Assignment names shows plainly; with none named ("His own", the Driver takes his usual Truck) his usual Truck shows in grey, or nothing if he has none.
- A **Draft** block has a dashed outline and a small "Draft" tag beside First or Then; an Assigned block looks plain, tagged only once it is Changed or Added (or Cancelled).
- Above the lanes, the day's count leaves cancelled Assignments out.
- A block can also show what the Truck did on it (phase 3): its Loads so far, **Now** or **Done**, and "since 08:24" when work on it began. Only when the Assignment carries a Trip part (`trips`) with at least one Trip. The day's read sends one on each Assigned Assignment a stored Trip matched: every Truck with stored visits that day (from the Fleet imports page) is built whole, as of that day's latest Import, exactly as the Fleet imports page's stored day opens, and matched as there (cancelled and discarded Assignments kept for matching, Drafts never). With the 16:20 cut imported, Randy's blocks on Mon 16 Nov read "4 Loads · Done · since 08:24" and "2 Loads · Done · since 11:30". An At-only Haul (At, no From or To) reads "Loads from Tickets · Done · since 08:24": the Truck cannot tell which way material went. Drafts, other blocks and a day with no stored visits look as above. The Simulation (`/simulate`) shows it on Truck 55's real day too.
- **Unplanned work on a real day** (shown, not answered: answering is spec #73's): Trips no Assignment explains, from the same whole-Truck days. Each piece shows after the blocks of the Driver at its time (the latest check-in to the Truck that day at or before it leaves), in the same amber as the Truck log's boxes: "1 Unplanned work", then its Places and times, "J25008 Los Flamboyanes ⇄ J611 Bishop Kearney · 14:15–14:43" (Randy checked in to Truck 55 at 06:00 on Mon 16 Nov, 16:20 cut imported: after his A2). A Driver with Unplanned work but no Assignments that day gets a lane for it. With no check-in to the Truck before it nobody is guessed: it shows in its own row under the lanes, "Driver not known · Truck 55", its avatar a solid amber ring with a ?, never in Unassigned (Unassigned means a Draft with no Driver, and has the dashed ring). A Trip two of a lane's Assignments fit equally is planned work, not Unplanned work: the lane asks "Which Assignment?", in the same amber, with the Trip's time, From and To ("08:24 J25008 Los Flamboyanes → Villager"). A lane with neither looks as before.

### Adding (the composer)
- The **+** on a lane (Unassigned included) opens the composer in that lane. While it is open that + turns to **×** ("Close the composer for Randy"), and tapping it again closes the composer, dropping what was picked. Another lane's + moves the composer there, blank.
- **Who?** is a row of the active Drivers as chips. The lane's own Driver is pressed and cannot be dropped; tapping another adds him (or drops him again), and each Driver picked gets the same Assignment as his own Draft, last in his lane, separate from then on. They are saved together: if one cannot be saved, none is. From Unassigned nobody is pressed; picking Drivers there gives it to them instead of Unassigned.
- At the top, **Haul | Move | Other** (a segmented toggle) says what kind of work it is, Haul chosen. Other is shown but cannot be chosen yet. The kind decides the rows: a **Haul**'s read in the order of the sentence, For, At, "Hauling what?", Pick up, Drop off; a **Move**'s are the machine, typed ("the 260 + big bucket", up to 100 characters), From and To, with "The machine is typed. No Material, no For. Not counted as Loads." Switching kind keeps what each kind's rows hold until Save, and Save sends only the fields of the kind chosen (a refused machine shows under its box).
- **At**, Pick up and Drop off are rows of Place chips, and "Hauling what?" is Material chips, each with "Or type it" for a name not in the list (found, brought back or added by the Worker). At, From and To are all optional and can be used together.
- **For** offers the active Foremen, then the active Customers, as two groups of chips, then "Or type it" (a Foreman with that name, else a Customer, else a new Customer: a typed For never adds a Foreman). Until Dave picks or types a For, it is filled in with the drop-off's usual Foreman if it is a job site, otherwise the pick-up's; once he has, no usual Foreman is filled in, so a Customer he picked is never joined by a Foreman. He can change or clear it.
- **At from For**: picking a For fills an empty At with its usual Place: a Customer's usual Place, or the one active job site a Foreman is the usual Foreman of (none when he is the usual Foreman of no job site or of several). Only active Places count, and an At Dave already chose is never overwritten. Under For it says so: "Picking Brody fills At with his usual Place." A job-site At never suggests a Foreman, so the two suggestions cannot feed each other.
- "Note or other truck" opens the Truck chips ("His own" first, the default) and the note. A Truck with an open Truck problem has a red mark on its chip (hover for the notes), and so does His own when the lane's Driver's usual Truck has one, on any day the composer opens, since a problem is the Truck's state now. The open problems are read again when the page regains the focus.
- With more than one Driver picked, each takes his own Truck: the Truck chips give way to a line saying so, and a certain Truck is named on his block afterwards.
- A sentence previews it ("Randy and Mike haul for Brody at TIUNY · Asphalt to Villager"; "Randy and Mike haul for Brody · 2\" minus from Villager to TIUNY"; without For, "Randy hauls 2\" minus from Villager to TIUNY"; a Move, "Scott moves the 260 + big bucket from Wintergarden to TIUNY"). Save needs only the day, puts it last in the lane and folds the composer. Every **+** opens a blank composer: nothing is carried over from the last one.

### Changing an Assignment
- Tapping a block opens it in its lane (one at a time; tapping again closes it) with **Haul | Move | Other** above a sentence of chips: a Haul's Driver, Material, From, To, Truck, For and At; a Move's Driver, machine (typed: tapping it opens its box), From, To and Truck; and its note.
- Changing the kind asks first, "Switch to Move? Material, For and At will be cleared." (to a Haul, "The machine will be cleared."), with **Keep Haul** and **Switch to Move**. Switching clears those fields in the same save. On an Assigned one it is a change like any other: marked Changed, and the Driver sees "was Haul".
- Tapping a chip offers that list (Unassigned for the Driver, His own for the Truck, "Leave blank" for the rest; For in two groups, Foremen then Customers; From, To, At, Material and For also "Or type it", as in the composer, saved by name on Enter or on leaving the box). Each pick, or the note when left, saves on its own.
- A new Driver puts it last in his lane. A Draft simply moves. An Assigned one is cancelled for the first Driver and a copy is added last in the new lane, where it stays open: Assigned at once to the new Driver (marked Added), or a Draft in Unassigned.
- **Do this first** and **Do this later** move it one place in its lane, each left out at that end.
- **✕** takes it off the day: a Draft is deleted; an Assigned one is cancelled, staying in its place, struck through and greyed, marked Cancelled, and opens only to **Put back**, which restores it (both count as Changed), or **Discard**. The button says **Delete** on a Draft and **Cancel** on an Assigned one.
- **Discard**, on a cancelled block (one tap, any day, past days too) or in its open Assignment, clears it off the Board: it leaves the lane, the week strip and the empty-day check. Nothing is deleted, and its Driver still sees it cancelled until he dismisses it.

### Days
- The header shows the day's short date and its word ("Mon, Nov 23 · Next Monday", with a Holiday's name).
- An arrow each side names the Working day it goes to, skipping weekends and the six Holidays; the left and right arrow keys do the same when no field has the focus. **Back to** returns to the next Working day from any other day.
- The day on screen is kept in the address (`?date=2026-11-23`), so a reload or a shared link shows the same day.
- A day with no Assignments at all (cancelled ones count) says "Nothing planned for Mon, Nov 23" (on today or later, adding "Use + on a lane to plan the day.") and saves nothing just for being looked at.
- A day before today says "This day is before today, so it is read-only.": its lanes have no **+**, its blocks do not open, and it has no Assign; Discard still works on its cancelled blocks.
- **Start from**: on today or a later empty day, copies the latest earlier day with Assignments ("Start from Thu, Nov 19"): each Assignment's Driver, order, kind (Haul or Move) and machine, Places (From, To and At), Material, For (Foreman or Customer) and named Truck, without notes or cancelled ones, leaving out removed Places, Materials, Trucks, Foremen and Customers; a removed Driver's work goes to Unassigned. Every copy is a Draft.
- **Copy to**: a day before today with Assignments offers to copy it to the next Working day while that day is still empty, by the same rules, then shows it.
- Neither is offered once the target day has Assignments.

### Assign
- Each Assignment is a **Draft** until Dave **Assigns** it on its own (ADR 0005); its Driver sees nothing of a Draft. There is no Send for the day and no "Assign all".
- On today and later days a Draft block with a Driver (not a removed one, whom no one would reach) has an **Assign** button in its corner: one tap, no confirm. The block then loses its dashed outline and Draft tag, and the week strip reads its states again. If the Worker refuses (a day now past, say) its message shows and the block stays a Draft.
- An Unassigned Draft has no Assign button; the Unassigned lane says "Pick a Driver to Assign" while it holds Drafts. Days before today show their Drafts but no Assign.
- Once Assigned, every change reaches the Driver at once, marked Changed (measured from when it was Assigned); one Assigned on its own day is Added. Days Sent before the change were carried over: their Assignments with a Driver are Assigned.

### Week strip
- A tile for each day Monday to Friday and narrow Saturday and Sunday tiles; today's says Today and the next day's Tomorrow; the day on screen is filled and today outlined.
- Each tile shows the day's state and a Holiday's name: "2 drafts" while it holds Drafts that are not cancelled (Unassigned ones included), otherwise Assigned, or Changed once any Assigned one is Changed, cancelled or Added, or "–" for nothing (a Holiday with nothing planned shows only its name). A dot in the tile's corner repeats the state at a glance: a hollow ring for drafts, green for Assigned, amber for Changed, none for nothing.
- Tapping a tile shows that day; the pager ("Nov 16 to Nov 22") moves a week at a time keeping the weekday; its arrows name the Monday of the week they go to ("‹ Nov 9", "Nov 23 ›").
- The strip reads the states again after any change on the Board and when the page regains the focus (if the week cannot be read, it says so under the tiles, which still show their days), and scrolls sideways on a phone.

## Driver view (`/driver`)

- **Scheduler | Driver** in the header switches to it. The first time it asks "Who are you?" with the active Drivers as large buttons; the device remembers the Driver and the view in its browser storage (nothing is saved in the database), so it opens on his day.
- Under the title his initials and name, with **Change**, which goes back to "Who are you?" (top left is "← Hub", as on every page); **Scheduler** switches back.
- It shows one of his days at a time, opening on Today: **Yesterday | Today | Tomorrow** are one tap (calendar days, so on a Friday, Tomorrow is Saturday), and **‹ ›** step one calendar day at a time, weekends included, each naming the day it goes to ("Wed 18", "Fri 20").
- When Dave has Assigned him work beyond tomorrow (not cancelled), **Next from Dave: Mon, Nov 23 →** goes there.
- He sees only his Assigned Assignments, never his Drafts; a day with none says "Nothing from Dave yet for Monday."
- Otherwise his Assignments are large cards in Dave's order, each with a coloured left edge (yellow, amber when Changed, green when Added, red when cancelled, whatever the kind), headed by its number and kind pill, "1 · HAUL" or "1 · MOVE" (blue). A Haul card leads with whom it is for in large type, "Haul for Ed" (with a grey "Customer" tag under it for a Customer; left out when For is blank), then an **At** line, the Material, Pick up and Drop off, each only when set, the note, and "Take Truck 53 for this one" when a Truck is named. A Move card leads with the machine in large type, then From and To lines, the note and the Truck.
- A card can also show what the Truck did on it (phase 3): "4 Loads · last 11:25" (its Loads and when the last one arrived), and **Now** on the Assignment he is on now. Only when the Assignment carries a Trip part (`trips`) with at least one Trip. His day's read sends the same Trip parts as the board's (each Truck with stored visits built whole, every Driver's Assignments on it, as of the day's latest Import), so the two never disagree. An At-only Haul reads "Loads from Tickets", with no last Load. With the 16:20 cut imported, Randy's cards on Mon 16 Nov read "4 Loads · last 11:25" and "2 Loads · last 13:54"; with only the 10:15 cut stored, his first card shows **Now** all day until a later Import. A day with no stored visits looks as above. The Simulation (`/simulate`) shows it on Randy's real day.
- **His Truck log** (Today only), under the cards all day: the same Truck log as on the Fleet imports page, of the Truck he checked in to today (his latest check-in), else his usual Truck, with "As of the Import at 16:25" under it; it fills in as Imports arrive. Header (Truck, date, start and end time, miles blank marked "meter reading", Driver, Total hours), one column per Assignment shown on that Truck, Unplanned work on the Truck (shown only, no Answer), "Which Assignment?" boxes and the drives to and from the shop. His Trips on a Truck he checked in to match his Assignments that day whatever Truck they name. With Randy checked in to Truck 55 and the 10:15, 13:05 and 16:20 cuts imported on Mon 16 Nov, it runs 06:24 to 16:03 with A1 and A2, the J25008 ⇄ J611 Bishop Kearney Unplanned work and the shop drives; with only the 10:15 cut stored it has no end time. Not shown on any other day, or while that Truck has no stored visits today.
- Marks: "Changed by Dave" with what each field was when it was Assigned ("was Cobblestone"; For is one field, so a switch from Foreman Ed to Customer Jaus says "was Ed" once; At by its Place's name; what the card's kind no longer shows goes under the mark instead, "was Haul · For was Ed · Material was Asphalt" on a Haul turned Move), "Added by Dave" (Assigned on its own day, or handed over from another Driver), or struck through and "Cancelled by Dave". A cancelled card has **Dismiss** in its bottom right corner, which clears it off his day (the Board is unchanged); Put back on the Board shows it to him again. Given to another Driver after it was Assigned, it shows Cancelled to the first and Added to the second.
- It reads today, the day shown and his next Assigned day again whenever the page regains the focus; Today moves on with the clock, a picked day stays.

### Check-in (Today only)
- On **Today**, until he has checked in, a **Check in** card sits at the top, above his Assignments (which still show below it). It is offered whether or not Dave has Assigned him anything, and never on Yesterday, Tomorrow or any other day. If his check-in today cannot be read, the page says "Could not load your check-in. It tries again when you come back to the page." and still offers the card, so he can always check in (the latest check-in counts).
- **Truck**: every active Truck as a large button, his usual one pre-selected (none when he has none or it was removed). **Start Inspection** then lists the Truck's open problems first, before the items, so he knows them before driving and does not report them twice: "Mud flap torn · reported Fri by Sample Driver B" (the day: "today", the weekday within the last week, or the date further back); none listed when it has none. Then the checklist in Dave's order. Picking another Truck once started starts a fresh Inspection for it: its open problems, no answers or notes yet, and a new Inspection id, so a Finish for the first Truck can never be saved, or retried, as this one.
- Each item is answered with one tap: **OK**, **Needs repair** or **N/A** (an optional item says "(optional)"). Needs repair asks "What needs repair?" for a short note. An optional **Other notes** box follows.
- Each Needs repair becomes a **Truck problem** on that Truck, with his note, his name and the time, saved together with the Inspection (a refused or retried Finish opens none twice). A Truck with an open problem can still be checked in to and driven: the app reports, it never grounds.
- **Finish** is allowed once every item that is not optional is answered and every Needs repair has its note. The Worker records the time (its clock) and today's date. A failed Finish says "Could not finish the check-in. Your answers are kept: try Finish again."; trying again sends the same Inspection id, so it is never saved twice.
- Once checked in, the card becomes one line: "Truck 24 · checked in 6:42 · **Report a problem** · **Check in again**" (time in US Eastern, 24-hour clock). Check in again opens the card again (with **Cancel** back to the line) for another Truck or the same one after a repair; the latest check-in counts and the earlier Inspections stay.
- **Report a problem**, at any time that day, asks "What is the problem?" (required: **Send to Dave** waits for a note) and reports a Truck problem on the Truck of his latest check-in today; **Cancel** puts it away. Once sent the line says "Sent to Dave: Hydraulics leaking". A failed send says so and keeps the note to send again. It is offered only on Today, once he has checked in; after Check in again to another Truck, reports go on that one.
- An Inspection is never changed or deleted (ADR 0006). Until Drivers sign in through the Hub, whoever picked the name on the phone is trusted, so Inspections are tried on staging, not used as the real record.

## Simulation (`/simulate`)

No page links to it: open it by its address. **Board** (top right) goes back to the Board, as from Settings.

Phase 3 run on one real day: Truck 55 (MCK-55-17), driven by Randy on Mon 16 Nov 2026, on the real HCSS Fleet data. The Trip builder (`shared/trips.ts`) works out everything below from what the Worker would know at the clock's time, with "sunset" (a road fence the Truck crosses twice, 61 s each time) as not considered, and the shared Truck log function (`shared/truckLog.ts`) turns its output into the Truck log columns, Unplanned work, "Which Assignment?" questions, shop drives and each Assignment's Trip part. Nothing is saved and the Worker is not asked.

- **Clock**: a slider over the day, opening at "end of day"; **Play** runs it in the 10-minute steps the Worker pulls Fleet (from 04:00 when at end of day), **Pause** stops it.
- **Scenario** picker for Dave's Assignments: As planned (A1 J25008 Los Flamboyanes → Villager, then A2 Walworth Dolomite → J25008), The other way round (A1 reversed), Reroute at 11:20 (A1's drop-off changed to J611 Bishop Kearney; Trips before 11:20 match A1 as it was). Two made-up scenarios (not Fleet data) show the cases the real day lacks: **Made up: Unplanned work to split** (A1 Walworth Dolomite → J25008 twice, then J25008 → J611 → Villager → J25008, which nothing explains, then the shop) and **Made up: Sam on Truck 55 too** (the real day, with A2 Sam's, naming Truck 55, and nobody checked in, so two Drivers fit and the Truck log asks "Who was driving?"). In every other scenario Randy checked in to Truck 55 at the start of the day.
- **Scheduler view**: Randy's lane on the real board blocks, each with its Trip part (Loads, Now or Done, since when), Changed once the reroute has happened. After his blocks, an amber "1 Unplanned work" when the Truck did work no Assignment explains (as planned, from the moment its first Trip arrives). Tapping it answers the Unplanned work (below). With no Unplanned work the lane is exactly as on the Board. An Assignment Dave made from Unplanned work is a block like any other, marked **From the Truck** (outlined), never Added.
- **Driver view**: his Today ("Today, Mon, Nov 16") on the real Driver cards, each with "4 Loads · last 11:25" and Now. An Assignment made from Unplanned work is not on it: Randy gets no notice of it.
- **Trip log** (to the right of the Scheduler and Driver views on a wide screen): every Trip the Truck made, as known at the clock's time, the drives from and back to the shop included (the day ends "15:41 · J25008 Los Flamboyanes → Shop · 18.39 · empty"). Each row: when it left, From → To, miles, its kind (**load**, **empty**, **at TIUNY** for an At Trip, **for Dave** when no Assignment explains it or two fit equally, **not a haul** once Dave says so; a Trip counts as soon as the Truck arrives), the Assignment it counts on ("–" for none), and the matching rule that decided it ("To or from the shop or a yard"). "No Trips yet at this time." before the Truck leaves.
- **Matching rules** (`shared/trips.ts`), the first that fits wins, and two Assignments fitting at one rule is a "Which Assignment?": 1 From and To match the Assignment (a Load); 2 its way back (empty); 3 to or from the shop or a yard (empty, no Assignment); 4 going to its pickup (empty); 5 leaving its pickup when its To is empty (a Load); 6 from a plant to its drop when its From is empty (a Load); 7 starting or ending at its At when it has only At (an **At Trip**: Now / Done, since and Trucking hours, never Loads; Why reads "Starts or ends at the Assignment's At"); 8 nothing fits (Unplanned work). Rules 1–6 read the route with At standing in for a missing end: "at J25008, to Villager" matches as J25008 → Villager and "from Walworth, at J25008" as Walworth → J25008, with real Loads. With From and To both set, At only gives the Job. An At-only Haul's Loads are blank, "Loads from Tickets", on its block, card and Truck log column; an At with no geofence code matches no Trip. Each Trip is matched against the route as it was when the Truck left, so a new At at noon leaves the morning's Trips as they were.
- **Truck log** (full width below), the paper Daily Truck Log filled in:
  - Header: Truck, date, start time (first ignition on or first exit from the shop, whichever is earlier), end time (while the day goes on, once the Truck is back at the shop or yard: its arrival, or a later ignition off; at end of day wherever it stopped: the later of its last arrival and last ignition off), start and end miles (the meter readings around the day; the end one from 22:12, when it was read), Driver (the Driver of the latest check-in to Truck 55 by the clock: Randy checked in at the start of the day, so every scenario but Sam's names him), or "Who was driving?" in red when nobody checked in (Sam's scenario: Randy's and Sam's Assignments both name Truck 55, and Dave's pick answers it), and Total hours. A box is blank until what goes in it is known.
  - One column per Assignment in Dave's order, headed "Assignment 1", "Assignment 2"…: Job (its To's, else its At's, else its From's: the first that belongs to a Job), Pick up, Drop off, Material, # of loads (blank, marked "from Tickets", for an At-only Haul), # of tons (from the Loads' Tickets; blank, marked "from Tickets", until they are read) and Trucking hours.
  - After Dave's, an amber box for each **Unplanned work**: every Trip in a row that no Assignment explains, between Trips an Assignment explains (or the shop). A drive back to a Place the Unplanned work already went to, which would otherwise only be guessed as a drive to some Assignment's pickup, is part of it. It shows its Places and times only, never a Pick up or Drop off, because the Truck cannot tell which way material went: as planned, "J25008 Los Flamboyanes ⇄ J611 Bishop Kearney · out 14:15, back 14:33 · 0.46 h" (14:15–14:43), and A1 keeps its 3.02 Trucking hours. It appears as soon as its first Trip arrives (14:23, when the Truck reached Bishop Kearney) and grows as the next arrives. A Trip two Assignments fit equally is not Unplanned work: it is planned work, kept as a "Which Assignment?" question. Its **Answer** button (or the lane's "1 Unplanned work") opens the answer. With the reroute at 11:20 there is none.
  - **Answering Unplanned work**: a dialog with the Unplanned work's line, then "How does Dave answer?", a segmented toggle of the three ways. **Make an Assignment** asks "Where did he load?" (one chip per Place of the Unplanned work) and the **Material** (Fill, 1&2 stone, Top soil, or "Or type it" for another); Save stays off until both are given. The answer makes an Assignment for Randy, Truck 55 and that day, Pick up where he loaded and Drop off where the Truck went next: Assigned, not Added, and shown as the next column, "Assignment 3 · From the Truck". The Trip builder re-matches with it, matching it only against the Trips of the Unplanned work it answers (never earlier Trips on the same route), so its Loads, Job and Trucking hours come from the rules and the Unplanned work is gone. As planned, "J611 Bishop Kearney" and "Top soil" give Job J25008 Los Flamboyanes, Pick up J611, Drop off J25008, 1 load, tons "from Tickets", Trucking hours 0.46; in the Trip log 14:15 is empty ("Going to the Assignment's pickup": before its first Load a drive to its pickup is never a way back) and 14:33 its Load. "J25008" instead gives the opposite route, Job J611, and 14:15 is the Load.
    - **Link to an Assignment** asks "Which Assignment?" (only that Driver's Assignments that day: A1 and A2 for Randy on 16 Nov; under "Who was driving?" only the picked Driver's) and "Where did he load?", as in Make an Assignment; Save stays off until both are given. It is recorded as a change to that Assignment's route (as the 11:20 reroute is) from the leave time of the Unplanned work's first Trip: Pick up where he loaded, Drop off where the Truck went next. The Assignment then shows **Changed** from that time on, and the Trip builder counts the Unplanned work's Trips for it by the rules. Like a made Assignment, the rerouted Assignment claims only the Unplanned work's own Trips; every other Trip keeps the match it had. As planned, A2 linked "loaded at J611 Bishop Kearney" becomes J611 → J25008 from 14:15: 14:15 is empty (to its new pickup), 14:33 its third Load, and its Trucking hours run 11:30 to 14:43 (3.21). Its Material stays as Dave planned it. An Assignment made From the Truck for another Unplanned work can be linked too: it is rerouted the same way and claims the Trips of both, but, made afterwards, it never shows Changed. On the made-up day, split at J611 → Villager, the first Unplanned work made "loaded at J25008" (A2) and the second linked to A2 "loaded at Villager" leave one column, "Assignment 2 · From the Truck", Pick up Villager, Drop off J25008, 2 loads, Trucking hours 1.08.
    - **Not a haul** takes an optional **Note** (fuel, repair, personal) and can be saved straight away. The Unplanned work is gone; its Trips stay in the Trip log, Kind "not a haul" and Why "Not a haul: fuel" (or just "Not a haul"), count on no Assignment, and still count in Total hours (9.88 as planned).
    - The answers are held on the page only; a new answer to the same Unplanned work replaces the earlier one, and changing the scenario clears them.
  - **Split**: Unplanned work of more than one Trip also offers "Split this Unplanned work at a Trip", one button per Trip after its first ("Split at 09:45 · J611 Bishop Kearney → Villager"). Tapping one splits it in two there; each is answered on its own, and its Trips are still the only ones its answer can claim. Which Trips are Unplanned work is decided as if nothing were split. On the made-up day, splitting at J611 → Villager gives "J25008 Los Flamboyanes ⇄ J611 Bishop Kearney · out 09:20 · 0.17 h" and "J611 Bishop Kearney ⇄ Villager ⇄ J25008 Los Flamboyanes · out 09:45, back 10:10 · 0.67 h"; loaded at J25008 (Top soil) and at Villager (Fill) they become two Assignments From the Truck, 1 load each, Trucking hours 0.17 and 0.67. An answer given to the whole Unplanned work before the split is dropped.
  - **Driver first**: when the Truck log asks "Who was driving?", the Unplanned work is on the lane of each Driver who fits, and answering asks "Who was driving?" first (one chip per Driver); the ways to answer appear only once one is picked. The made Assignment is that Driver's (on his lane, naming Truck 55), and Link to an Assignment offers only his Assignments (Sam's A2, not Randy's A1), and the pick (made or linked) answers the header's question: its Driver box then shows that Driver, and later answers are not asked again. With one Driver who fits, nothing is asked.
  - **To and from the shop**: the drives out of the shop and back to it, as "15:41–16:03 · J25008 Los Flamboyanes → Shop · 18.39 mi · empty" ("None yet" before the Truck leaves). Empty by rule: Fleet cannot see a load, and Trucks do not load at the shop.

## Fleet imports (`/fleet-imports`)

Linked from the Board's header as **Fleet imports**, next to Settings; **Board** (top right) goes back. Where Dave drops each HCSS **Fleet export** as it comes, several times a day.

- **Drop zone**: drop the entry/exit report exported from HCSS Fleet as JSON or xlsx (or tap it to pick one or more files). Each file is one **Import**. The page reads the file itself (for JSON, the `Result` array, or a bare array, of EquipmentCode, GeofenceCode, Entry/ExitDateTime and Entry/ExitOdometer) and sends the rows to the Worker; the Worker never parses files.
- **xlsx exports**: the entry/exit report as Fleet saves it to xlsx (the real 16 Nov file, `2026-11-16-EntryExitReport.xlsx`) is one sheet named "Sheet", every cell text or a number (no Excel dates):
  - Row 1 is the header: Location Code · Location Description · Entry Time · Exit Time · Duration · Calculated Mileage.
  - A row "Entry Date: 11/16/2026" (M/D/YYYY, US Eastern, the other cells empty) starts each day.
  - Each visit is a row under its day: the geofence code ("SHOP", "J25008 Los Flamboyanes", "sunset"), its description (may be empty), entry and exit as US Eastern wall times with seconds ("07:02:03 AM"), the duration in hours and the mileage (neither is read).
  - It has **no EquipmentCode and no odometers**. So when an xlsx is dropped the page asks "Which Truck is EntryExitReport.xlsx for?" with a chip for each active Truck that has an HCSS code ("Truck 55 (MCK-55-17)"); the picked chip turns yellow until the Import is done, and the rows get that Truck's HCSS code, and their odometers are blank. With no Truck having an HCSS code it says to set one in Settings.
  - Times are read as US Eastern explicitly (`America/New_York`, daylight saving included), never the browser's zone, and sent in UTC, so an xlsx visit and the same visit from a JSON export meet on the entry minute.
  - Fleet cuts visits at midnight: a visit still there at the end of a day has exit "12:00:00 AM". When the file's next day starts with the same geofence code at "12:00:00 AM", that midnight is its exit (Fleet's own split, as the JSON gives it); otherwise the Truck is still there and the visit is stored open.
  - A blank Exit Time means the Truck was still there when the report was run (an export taken during the day): the visit is stored open, and a later Import closes it.
  - The 16 Nov file starts with 15 Nov: the Shop from 00:00 to midnight. So it holds 20 visits, not 19: the 15 Nov Shop day and the 19 of 16 Nov (the JSON's 18 plus the Shop from 16:03, still open). Dropped alone it says "20 new" ("Sun 15 Nov: 1 new; Mon 16 Nov: 19 new"); dropped after the 15:02 JSON it says "2 new · 1 closed · 17 already stored" (the 15 Nov Shop and the 16:03 Shop added, J25008 closed at 15:41:56).
  - The xlsx library (`read-excel-file`) is loaded only when an xlsx is dropped on this page; no other page downloads it.
- The rows' EquipmentCode finds the Truck by its HCSS code. Each export repeats the day so far, so each visit is kept once: the same visit is the same Truck, geofence code and entry minute (the entry time in UTC cut to the minute). A re-entry to the same geofence in the same minute is merged into one visit (accepted), keeping the most exact entry time any row gave (with seconds over only to the minute). A visit still open in the export (no exit) is stored with no exit time. The Import is recorded with the US Eastern days its visits were entered on.
- **Newer and older exports**: a row with an exit closes a stored visit that was still open, and the visit records that Import. A closed visit is never reopened or changed by an older export dropped later, so the order files are dropped in doesn't matter. A visit keeps the most exact entry time any export gave: an entry with seconds replaces one given only to the minute.
- Under the drop zone, each Import of this visit as a card, newest first, rising in as it comes: "6 new · 1 closed · 7 already stored" (visits it stored, open visits it closed, and visits it held that were stored already), then the file's name and the Truck ("EntryExit-1502.json · Truck 55"), then each day it touched with that day's counts ("Mon 16 Nov: 3 new · 1 closed; Tue 17 Nov: 5 new"; closed and already stored only when there are some). The counts are kept with the Import. Dropping the 16 Nov JSON again says "0 new · 0 closed · 18 already stored"; the 10:15, 13:05 and 16:20 cuts in that order say 8/0/0, 6/1/7 (closing J25008, open since 10:00) and 5/0/14, and the Shop visit from 16:03 stays open.
- **Refused files**: an Import that would mix the wrong data into a Truck's day is refused; the drop says "EntryExit-1502.json was not imported" and why, and nothing is stored. The reasons: "No Truck has the HCSS code MCK-55-17. Set it in Settings." (no active Truck has the file's EquipmentCode; a removed Truck counts as none), "The file must hold one Truck." (more than one EquipmentCode), a file that is not a Fleet export (the page says so before sending; the Worker refuses such rows too: "This is not a Fleet export. …"), and "Fleet imports are allowed only on local, preview and staging." (the Worker's `ENVIRONMENT` is not `local`, `preview`, `staging` or `test`; an allow-list, so unset is refused, and production never takes an Import).
- **Days touched**: each visit is filed under the US Eastern date it entered, so an export that spans midnight or a date range fills in each of its days, and the Import is linked to each of them. A visit entered at 23:50 Eastern is filed under that day, though in UTC it is the next.
- **Codes with no Place**: under an Import's days, every geofence code in it that no active Place has and that is not turned to **Not considered** in Geofences (codes match ignoring case), however short the visits there: "BROCKPORT", "GAS STATION". Their visits are stored all the same and nothing is refused for them; giving a Place that geofence code in Settings sets it up. Each code has **Don't consider**, which turns that Geofence to Not considered (Settings) at once: it leaves the list, and the stored day below is read again without its visits. If that fails, the code stays and a toast says "Could not turn GAS STATION to Not considered". Not shown when every code has a Place or is not considered.
- **Stored day** (below the Imports): a chip for each **Truck** (the active Trucks with an HCSS code; the first one picked at first) and the days as on the Driver view: ‹ › naming the day they go to ("Sun 15"), one calendar day at a time, with **Yesterday | Today | Tomorrow** between them (today at first); the heading names the day ("Stored day · Mon, Nov 16"). After an Import it shows that Import's Truck and the last day it touched. It reads the Truck's stored day from the Worker (`GET trucks/:id/days/:date`); when that fails it says "Could not load the day. It tries again when you pick a Truck, a day or a time." It shows:
  - "As of the Import at 16:25": the time of the latest Import that covered that Truck's day, or "No Import has covered this day yet."
  - The day's **codes with no Place**, as an Import lists them, each with **Don't consider**.
  - The **replay clock**, the Simulation's: a slider over the day and **Play**, which moves it on in 10-minute steps (from 04:00 when at end of day), **Pause** stops it. It opens where the Worker opens the day: a past day at "end of day" (23:59), today at the time of the latest Import. Each move reads the day again at that minute (`?at=HH:MM`, the end of the minute, never past the latest Import), and every view below follows it; the day stays on screen while it reads. A new Truck, day or Import opens the clock afresh.
  - The **Scheduler view**: the real board lanes, one for each Driver with Assignments on the day, each block with its Trip part ("4 Loads · Done · since 08:24") at the clock's time, and the Unplanned work and "Which Assignment?" exactly as the board shows them (in the lane of the Driver at each piece's time, else the "Driver not known · Truck 55" row; shown, not answered). With the 16:20 cut stored, Mon 16 Nov opens with Randy's A1 "4 Loads · Done · since 08:24" and A2 "2 Loads · Done · since 11:30"; at 10:02 A1 reads "2 Loads · Now · since 08:24" and A2 has nothing yet.
  - The **Driver view**: each of those Drivers' Today on the real Driver cards, as the Simulation shows Randy's: "4 Loads · last 11:25" and "2 Loads · last 13:54" at the end of Mon 16 Nov.
  - The **Truck log**, the same component as the Simulation's, at the clock's time (at 10:02 on Mon 16 Nov, A1 has 2 Loads in 1.59 h and no end time). Header: Truck ("55 (MCK-55-17)"), date, start and end time, start and end miles, Driver and Total hours. Body: one column per Assignment (Pick up, Drop off, Material, Loads, tons "from Tickets", Trucking hours), the Unplanned work and "Which Assignment?" boxes as the Simulation shows them (no Answer button: answering is the Simulation's only), and the drives to and from the shop. With the 16:20 cut stored, Mon 16 Nov (a past day) runs 06:24 to 16:03 (9.64 h), A1 has 4 Loads in 3.02 h and A2 2 Loads, and the shop drives are 06:24–07:02 and 15:41–16:03. Start and end miles are blank, marked "meter reading": no meter readings exist yet. Start and end times come from the visits; until the day is over the end time shows only once the Truck is back at the Shop (with only the 13:05 cut stored, today, there is none).
  - The **Trip log**, the same component as the Simulation's: every Trip up to the clock's time, Load or empty, the Assignment it counts on ("A1", "A2": the Truck's Assignments that day in Dave's order) and why. With the 16:20 cut stored, Truck 55 on Mon 16 Nov starts with 06:24 Shop → J25008 Los Flamboyanes, has 4 Loads on A1 (J25008 → Villager) and 2 on A2 (Walworth → J25008), and ends with the 15:41 J25008 → Shop drive. A day with no stored visits says "No Trips yet".
  - How the Worker builds the day (all matching is the Trip builder's, `shared/trips.ts`; the Worker only gathers its inputs):
    - **Visits**: the Truck's stored visits entered on that US Eastern day.
    - **Assignments**: that day's Assigned ones naming the Truck (or, naming none, whose Driver's usual Truck it is), and every one that day of a Driver who checked in to the Truck, whatever Truck it names (shown in the Truck log only once one of its Trips is on this Truck). Drafts match nothing. Cancelled ones are kept, so a Trip before the cancel still matches; discarded ones too (discarding only hides a cancelled card: its earlier Trips never turn into Unplanned work), though they are not shown in the Truck log's columns. Their route changes are read too, so a Trip matches the route as it was then.
    - **Not considered**: the visits to a code turned to Not considered in Geofences (Settings), as the toggles are now, are dropped before Trips are built, however long the Truck stayed, so the day reads as if the Truck drove straight past. Every other visit is a stop, however short. Turning a code off or back on re-reads every day, past ones included. On Mon 23 Nov Truck 53 stopped at GAS STATION 06:40–06:44 on its way out and crossed WEITSMANS for 61 s on one way back to Villager: with both turned off the day has 9 Loads Villager → J2601 Talmudical, no Unplanned work and no gas station in the Trip log, and it ends at the shop at 16:01; without them the drive from the gas station to J2601 Talmudical is Unplanned work, and so is the drive from J2601 Talmudical to WEITSMANS.
    - **As of**: the day is built as of its latest Import, never the Worker's clock, so what a later export would say is never guessed.
    - **Clock**: a past day opens at its end (23:59), and is then over, so the day ends at its last arrival; today opens at the time of the latest Import. A clock minute means the end of that minute (HH:MM:59), as in the Simulation.
    - **Driver from check-ins**: the Truck's check-ins that day (each Inspection naming it, at its time; one from an earlier day never counts) go into the Trip builder. The Driver at a Trip's time is the Driver of the latest check-in to the Truck at or before it, and the Trip matches only that Driver's Assignments that day, whatever Truck they name; when two Drivers checked in, each counts from his time on (A at 06:00, B at 12:00: the header and the replay clock name A before 12:00 and B from 12:00). The header names the Driver at the clock's time. With no check-in before a Trip nobody is guessed: the header asks "Who was driving?" and the Trip matches the Assignments that name the Truck (Randy's A1 and A2 still get their Loads through his usual Truck 55). The board and the Driver page read the same Trip parts. Each piece of Unplanned work belongs to the Driver at the time it leaves, so on a handover each Driver's lane shows his own.
    - **Miles**: no meter readings, so start and end miles stay blank. Trip miles come from the visits' odometers; an xlsx export gives none, so a Trip from or to a visit stored only from an xlsx (or closed by one) is made all the same, its miles blank (an empty Miles cell in the Trip log, none on a shop drive). The 15:02 JSON then the xlsx give the same day as the 16:20 cut, ending 16:03 back at the Shop.
- **Start over** (at the bottom), for testing Imports again from nothing: **Clear Fleet imports**, then **Yes, clear them** (or Cancel), deletes every Import, the days each covered and every stored visit, on every Truck (`DELETE fleet-imports`). So the Board's blocks lose their Trip parts and Unplanned work, the Driver page loses its Truck log, and every stored day here says "No Import has covered this day yet."; the same file then imports as new again. The Imports list empties and a toast says "Cleared 2 Imports · 14 visits". The switch **Also clear Geofences and their Not considered toggles** deletes every Geofence too (the next Import brings its codes back, considered). Drivers, Trucks, Places (and their geofence codes), Assignments and check-ins are kept. Like Imports, allowed only on local, preview and staging.
- Test fixtures (`shared/fixtures/fleet/`): the 16 Nov JSON pulled at 15:02 (18 visits, J25008 from 14:43 still open), cuts of the whole day at 10:15, 13:05 and 16:20 (visits entered by then, later exits blank; 8, 14 and 19 visits), and the real 16 Nov xlsx export.

## Settings (`/settings`)

- Every list on one page: Drivers, Trucks, Places, Materials, Jobs, Foremen, Customers and the Inspection checklist; under Trucks, **Truck problems**; and last, **Geofences**.
- Each entry is a chip with its key detail: a Truck only its number; a Place its kind (Plant, Job site, or Shop or yard: shop and yard read as one), and a job site also its usual Foreman, as in "TIUNY · Job site · Brody", set in its panel.
- **Customers**: under Foremen, the people outside the company Dave hauls for (Jaus, Empire). Each has a name and an optional **Usual Place**, picked from the Places in use (a removed Place is not offered); the panel says "Picking Jaus on an Assignment fills At with this Place, if set". Leave it blank for a Customer whose sites change. Nothing is seeded. **One name across Foremen and Customers**: a name any Foreman or Customer already has, in use or removed, ignoring case, is refused with the reason on the Name ("Sample Foreman A is a Foreman already.", "Jaus is a Customer already."), so a typed For is never ambiguous. 
- **Codes for Fleet exports**: a Truck's panel has an **HCSS code** (its EquipmentCode in HCSS Fleet, e.g. MCK-55-17), by which an Import finds its Truck; a Place's panel has a **Geofence code**, by which a Trip finds its Place. Both are optional and saved trimmed; clearing one removes it. A Place with a geofence code says "On the truck map", one without says "Not on the truck map yet". A geofence code another active Place has (ignoring case) is refused with a reason on the field ("This geofence code is on Sample Plant already. Clear it there first."); one held only by a removed Place can be used, and bringing a removed Place back is refused while an active Place has its code. An HCSS code another active Truck has is refused the same way ("This HCSS code is on Truck 21 already. Clear it there first."), so an Import always finds one Truck. The Truck's HCSS id is not shown or asked for. No real Trucks or Places are seeded: on staging Dave sets up the real Truck and Places himself (ADR 0008 (PR #82)).
- Tapping one opens a panel to edit it; **+ Add** opens the same panel for a new one. Nothing is saved until **Save**, which saves what changed in one go and closes the panel; **Cancel**, Esc or a tap outside closes it and drops the changes without asking. A refusal (a name already in the list, a geofence code another Place has) or a failed save keeps the panel open with what was typed.
- **Remove**, on the left of the panel, makes one inactive after asking (warning how many later days still hold a Driver's Assignments) and drops any unsaved changes. Nothing is ever deleted: old Assignments, Inspections and Truck problems keep the name. Removed entries are not shown in Settings. Adding one again by its name (ignoring case) brings the removed entry back instead of refusing, says "brought back", and keeps what it had unless the add fills it in; typing a removed Place's or Material's name on an Assignment brings it back too.
- **▲▼** by each Driver, Place, Material and Inspection item put them in Dave's own order, which the lanes and the composer's chips (and later the Inspection) follow; a new or brought-back entry goes last (also one typed in the composer).
- **Truck problems**: what Drivers reported wrong with a Truck (each Needs repair in an Inspection, and each Report a problem during the day). Open ones first, then fixed ones, each newest first; each shows its Truck, note, who reported it and when ("Sample Driver B · Mon, Nov 23 9:00", US Eastern), with "· reported during the day" on one that came from Report a problem rather than an Inspection. **Mark fixed** asks "How it was fixed (optional)", then **Save** closes it; it stays listed under Fixed with when and the note ("Fixed Mon, Nov 23 10:15 · New flap fitted"), so a Truck's history is never lost. Only Drivers report problems: there is no Add.
- **Inspection checklist**: the items a Driver answers in an Inspection, starting with the paper Daily Truck Log & Inspection's 12 in its order (Dump box clean … Suspension). Each item's panel has its wording and an **Optional** switch (saved at once; the chip then says "Optional"), meaning a Driver may finish without answering it. New wording is used from the next Inspection on. The starting items are reference data loaded in every environment (`seed/inspection-items.sql`); loading it again never undoes Dave's changes. Drivers answer it when they check in (Driver view); each Inspection keeps the wording as it was.
- **Geofences**: every geofence code the app knows, by code: HCSS's Location list (loaded once on staging) and every code an Import brought (a new one comes in considered, e.g. "sunset", which HCSS's list lacks). A search box narrows the list to the codes holding what Dave types, ignoring case ("gas" finds GAS STATION); at most 100 rows show at once, with "100 of N shown" under them. Each code has a switch, on while it is considered. Turned off, it is **Not considered**: a code that is never work, such as a fuel stop, a diner or a road fence ("GAS STATION", "WEITSMANS", "sunset"). A visit to it is dropped before Trips are built, however long the Truck stayed, on every Truck and every day, past days included; a code turned on is always a stop. It needs no Place. The switch moves at once; if the save fails it goes back and a toast says "Could not save GAS STATION". There is no Add or Remove: codes come only from HCSS and Imports (Start over on the Fleet imports page can clear them all). The Fleet imports page's **Don't consider** turns a code off too.
