# Not considered geofences replace the 2-minute drive-through rule

The Trip builder used to drop any closed visit shorter than 2 minutes as a drive-through and keep every longer one as a stop, and a Trip into a visit was not written until that visit had lasted 2 minutes. Tuned on the 16 Nov day, the rule was wrong both ways on real days: a 4-minute fuel stop (GAS STATION on 23 Nov) was kept, so the drive from it to the job site fitted no Assignment and became Unplanned work, while a quick dump at a real Place could be dropped. A time limit cannot tell a quick dump from a drive-by, so tuning it only moves the problem.

Dave knows which fences are never work, so he says so once: he turns the code to **Not considered** in Settings. The Trip builder takes the codes turned off as an input and drops every visit to one of them before Trips are built, however long the Truck stayed ("Not considered: GAS STATION"). **Only the toggle decides**: the 2-minute rule is removed, a visit to any other fence is a stop however short, and a Trip counts as soon as the Truck arrives (the Trip log's "waiting" kind is gone). The toggles are read as they are now for every day, past ones included, so turning a code off or back on re-reads every day and loses nothing: the visits stay stored. The Simulation passes "sunset" as not considered, so its 16 Nov day reads as before.

**Where the codes live (issue #106, replacing the typed list of #105).** At first the codes were a free-typed Not considered list, a list like the others in Settings; Dave had to know and spell each code exactly, and nothing told him which codes exist. Now a **Geofence list** (`geofences`) holds every geofence code the app knows, with only two columns, `code` (unique, ignoring case) and `not_considered`. It is filled from HCSS's Location list, loaded once on staging and kept out of the repo, and by every Import, which adds each code it brings that is not known yet, considered (e.g. "sunset", which HCSS's list lacks). Settings shows it as a searchable list with one switch per code; the Fleet imports page's Don't consider turns the switch off. The migration copied the codes in use on the old list over turned off (and every code in a stored visit, considered); the old `not_considered` table is left unused, as migrations only add. Codes are never added or deleted by hand, so a typo cannot create one.

## Considered Options

- **Tune the time limit (or make it per Place).** Rejected: no limit separates a fuel stop from a quick dump; it only moves which real days are wrong.
- **Keep the 2-minute rule as well as the list.** Rejected: a real stop under 2 minutes would still vanish, and two rules make it hard to say why a visit was skipped.
- **Mark the codes on Places instead of a separate list.** Rejected: a fuel stop or road fence is not a Place Dave plans with, and it would clutter every picker.
- **Per-Truck or per-day lists, or a list frozen per day.** Rejected for now: a fence that is never work is never work, and a past day that re-reads when the list changes is what Dave wants when he adds a code he forgot.
- **Keep the typed list, with suggestions.** Rejected (#106): Dave still has to know a code exists before he can skip it, and a typo silently skips nothing.
- **Descriptions, types or cities of geofences in the table.** Not now: only the code and the toggle are needed to skip a fence; more columns can be added later.
- **Answer each such Trip as "Not a haul".** Not instead: that stays for one-off stops on one day; the list is for fences that are never work.
