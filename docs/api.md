# API

The Worker's HTTP API, which the page uses. Shapes are typed in `shared/types.ts`; the day rules (Working days, Holidays, Changed and Added, day states) are in `shared/days.ts`. Words in capitals are defined in [`GLOSSARY.md`](../GLOSSARY.md).

Under `/api/` standalone or `/truck-dispatch/api/` under the Hub. No sign-in yet; Cloudflare Access protects previews and staging.

| Route | Answer |
|---|---|
| `GET health` | `{ ok, environment, commit }` |
| `GET drivers`, `GET trucks`, `GET jobs`, `GET places`, `GET materials`, `GET foremen`, `GET inspection-items` | `{ drivers: [{ id, name, defaultTruckId, sortOrder, active }] }`, `{ trucks: [{ id, number, hcssCode, hcssGuid, active }] }`, `{ jobs: [{ id, name, jobNumber, active }] }`, `{ places: [{ id, shortName, fullName, kind, jobId, usualForemanId, onTruckMap, sortOrder, active }] }`, `{ materials: [{ id, name, sortOrder, active }] }`, `{ foremen: [{ id, name, active }] }`, `{ "inspection-items": [{ id, label, optional, sortOrder, active }] }`. Drivers, Places, Materials and Inspection items come in Dave's own order (`sortOrder`, 1 first), then those with none (`sortOrder` null) by display name; the other lists by display name (name, number or label): active entries only; `?include=inactive` for every entry. A Place's `kind` is `plant`, `job_site`, `shop`, `yard` or null (Settings offers shop and yard as one, Shop or yard, saved as `shop`); its geofence code is not part of the API, only `onTruckMap`, whether it has one, which is never saved from the page. An Inspection item's `optional` is true when a Driver may leave it unanswered. Only a job site has a `usualForemanId`; it is emptied when the Place stops being one, and an Assignment keeps its own Foreman, so changing it never rewrites a planned or past day |
| `POST drivers`, `POST trucks`, `POST jobs`, `POST places`, `POST materials`, `POST foremen`, `POST inspection-items` | JSON with the display name and any other field → 201 `{ driver }` / `{ truck }` / `{ job }` / `{ place }` / `{ material }` / `{ foreman }` / `{ inspectionItem }`, or 400 `{ fields }` (missing or blank name, a name already in the list ignoring case, an `optional` that is not true or false (left out, it is false), unknown usual Truck or Job, a kind not in the list, a usual Foreman who is unknown or removed, or on a Place that is not a job site) |
| `PATCH <list>/:id` (drivers, trucks, jobs, places, materials, foremen, inspection-items) | JSON with only the fields to change, including `active: true/false` → 200 with the entry as for POST; 400 as for POST; 404 if it does not exist. There is no delete: an entry is made inactive. A new entry of Drivers, Places, Materials or Inspection items (also one typed for an Assignment), and one brought back (`active` false to true), goes last: it gets the `sortOrder` after the highest, after giving every entry still without one a `sortOrder` in the order the list is read, so nothing else moves |
| `PUT drivers/order`, `PUT places/order`, `PUT materials/order`, `PUT inspection-items/order` | JSON `{ order: [id, …] }`, the whole list first to last (removed entries may be included) → 200 `{ drivers }` / `{ places }` / `{ materials }` / `{ "inspection-items" }`, every entry including removed ones, in the new order. Each id gets `sortOrder` 1, 2, 3…; entries left out get none. 400 `{ fields: { order } }` if it is not a list of ids of that list, each once; nothing changes then |
| `GET drivers/:id/later-days` | `{ laterDays }`: how many days after today (US Eastern) hold one of the Driver's Assignments, for the warning before he is removed. 404 if the Driver does not exist |
| `GET drivers/:id/next-assigned` | `{ date }`: the first day after tomorrow (US Eastern) that holds one of the Driver's Assigned Assignments that is not cancelled (his Drafts do not count), or null, for the Driver view's "Next from Dave". 404 if the Driver does not exist; 405 for anything but a read. (It was `next-sent`, now 404.) |
| `GET drivers/:id/days/:date` | The Driver view: one Driver's day → `{ date, assignments }`: only his Assigned Assignments (`assignedAt` set; his Drafts are left out, as Drivers see nothing of a Draft), as `GET assignments` gives them, cancelled ones included, in Dave's order. A day with none Assigned answers `assignments: []` ("Nothing from Dave yet"). Each has `was`: for a Changed one (`sinceSent` `'changed'`), each of `truckNumber`, `fromPlaceName`, `toPlaceName`, `materialName`, `foremanName` and `note` that is not as it was when it was Assigned, with the name it had then (null for empty; a null `truckNumber`, his own Truck); otherwise `{}`. A rename of an entry is not a change. Days before today are read too. 400 `{ fields: { date } }` for a date that is not real; 404 if the Driver does not exist; 405 for anything but a read |
| `GET today` | `{ today, tomorrow, nextWorkingDay }`, dates in US Eastern time; `nextWorkingDay` is the first weekday after today that is not a Holiday (New Year's Day, Memorial Day, Independence Day, Labor Day, Thanksgiving, Christmas; a weekend Holiday is not moved) |
| `GET assignments?date=2026-11-20` | `{ assignments: [{ id, date, driverId, driverName, truckId, truckNumber, fromPlaceId, fromPlaceName, toPlaceId, toPlaceName, materialId, materialName, foremanId, foremanName, note, position, createdAt, updatedAt, changedAt, cancelledAt, assignedAt, handedFromId, sinceSent }] }`, Drafts and Assigned ones alike. `assignedAt` is when Dave Assigned it, null for a Draft; `handedFromId` is, on the copy made by giving an Assigned Assignment to another Driver, the id of the one it was handed over from, otherwise null; `cancelledAt` is when ✕ cancelled it (only an Assigned one is cancelled), null when it is not cancelled, and a cancelled one keeps its place; `sinceSent` is `'added'` for one Assigned on its own day (US Eastern) or handed over (`handedFromId` set), `'changed'` for one whose `changedAt` is after its `assignedAt`, otherwise null (always null on a Draft), also in the answers that add, change or Assign one; Place names are short names; `changedAt` is when it last really changed, null until then; a null `truckId` means "His own": the Driver takes his usual Truck. Listed by lane (in the Drivers' order as their list reads, no Driver last), then `position` (its place in the lane, from 0), then creation time. 400 `{ fields: { date } }` without a real date |
| `POST assignments` | JSON `{ date, driverId?, truckId?, fromPlaceId?, toPlaceId?, materialId?, foremanId?, note? }` → 201 `{ assignment }`, a Draft, last in its lane (its date and Driver, or Unassigned), or 400 `{ fields: { name: message } }` (bad date, unknown Driver, Truck, Place, Material or Foreman, note over 1000 characters). From and To may be the same Place. Unknown fields are ignored. Instead of an id, a Place or Material may be typed by name as `fromPlaceName`, `toPlaceName` or `materialName`: the entry with that name, ignoring case, is linked; a removed (inactive) one is made active again; otherwise a new one is added (a Place with no kind). This happens in the same request: if the Assignment is refused or not saved, nothing is added or brought back. 400 `{ fields }` on that name field for a blank name, one over 100 characters, or a name given together with the field's id |
| `PATCH assignments/:id` | JSON with only the fields to change, of `driverId`, `truckId`, `fromPlaceId`, `toPlaceId`, `materialId`, `foremanId`, `note`, and typed names as for POST: a field left out stays as it is, an empty one (null or `""`) is cleared → 200 `{ assignment }`. A real change of Driver puts it last in his lane (its date and Driver, or Unassigned); a real change sets `updatedAt` and `changedAt` to now and, once it is Assigned, keeps its fields as they were before (ids and names, note, position) in the add-only `assignment_changes` record; fields sent as they already are (the same Driver again, say) change nothing, not even those times. A Draft's change of Driver simply moves it. Once it is Assigned, a real change of Driver does not move it: it is cancelled (`cancelledAt` and `changedAt` now, its earlier fields kept) and a copy with the fields sent (the rest as they were, note included) is added last in the new lane, created now: given to a Driver, the copy is Assigned at once (`assignedAt` now, `handedFromId` the first one's id, so it is Added); given to Unassigned, it is a Draft → 200 `{ assignment: <the copy>, cancelled: <the first one> }`. A cancelled Assignment cannot be changed: 409 `{ error: 'cancelled', message }` until it is put back. The day is fixed: `date` may be sent only as it is; any other is 409 `{ error: 'day_fixed', message }`. 400 `{ fields }` as for POST; 404 if it does not exist. There is no PUT (405) |
| `POST assignments/:id/move` | JSON `{ direction }`, `"earlier"` (Do this first) or `"later"` (Do this later) → 200 `{ assignments }`: its lane (its date and Driver, or Unassigned) in its new order, swapped with its neighbour and numbered 0, 1, 2… again. Only the one moved gets `updatedAt` and `changedAt` (and, once it is Assigned, its earlier fields kept and the Changed mark); the neighbour that shifted does not. 409 `{ error: 'lane_end', message }` when it is already first (earlier) or last (later); 409 `past_day` on a day before today; 409 `cancelled` for a cancelled one; 400 `{ fields: { direction } }` for any other direction; 404 if it does not exist; 405 for other methods |
| `DELETE assignments/:id` | ✕. A Draft → 204, a real delete, nothing kept. An Assigned one is cancelled instead → 200 `{ assignment }` with `cancelledAt`, `changedAt` and `updatedAt` now, its earlier fields kept in `assignment_changes`; it stays in its place and the day. One already cancelled is answered as it is. 409 `past_day` on a day before today; 404 if it does not exist |
| `POST assignments/:id/assign` | Assign: gives the Assignment to its Driver → 200 `{ assignment }` with `assignedAt` and `updatedAt` now (`sinceSent` `'added'` when Assigned on its own day, US Eastern). From then on its Driver sees it, and every change to it is kept and marks it Changed (ADR 0005). One already Assigned is answered as it is, keeping its first `assignedAt` (no Assign again, no lock). 409 `{ error: 'unassigned', message }` for one with no Driver (it stays a Draft until it has one); 409 `driver_removed` for one whose Driver was removed (no one would see it); 409 `cancelled` for a cancelled one; 409 `past_day` on a day before today; 404 if it does not exist; 405 for other methods. There is no Assign all |
| `POST assignments/:id/put-back` | Put back: clears `cancelledAt` → 200 `{ assignment }`, with `changedAt` and `updatedAt` now and its earlier fields kept (so it is Changed). One not cancelled is answered as it is, nothing changed. 409 `past_day` on a day before today; 404 if it does not exist; 405 for other methods |
| `POST days/:date/send` | Gone: 410 `{ error: 'gone', message }` to any method. Each Assignment is Assigned on its own instead (`POST assignments/:id/assign`; ADR 0005). Days Sent before were carried over: every Assignment with a Driver on such a day, and every cancelled one, was Assigned when the day was first Sent (or when it was made, if later); the rest stayed Drafts, so a cancelled Assignment is never a Draft. The `day_sends` table is kept but no longer read |
| `POST inspections` | Check in: JSON `{ id, date?, driverId, truckId, answers: [{ itemId, answer, repairNote? }], otherNotes? }` → 201 `{ inspection }`, saved for today (US Eastern) with `doneAt` the Worker's clock now. `inspection` is `{ id, date, driverId, driverName, truckId, truckNumber, doneAt, otherNotes, needsRepair, answers: [{ position, itemId, label, answer, repairNote }] }`: the answers in the checklist's order (`position` from 0), each with the item's wording as it was (`label`), `answer` `ok`, `repair` or `na`, `repairNote` only on `repair`; `needsRepair` is true when any answer is `repair`. The phone makes `id` (a UUID) when the Driver starts: an `id` already saved answers 200 with that Inspection as it was saved, and saves nothing, whatever else is sent (a retried Finish). 400 `{ fields }`: `id` not a UUID; `date` sent and not today ("Check in only on today"); `driverId` or `truckId` missing, unknown or removed; `otherNotes` not text or over 1000 characters; `answers` not a list; and per item, under `answers.<itemId>`, an item that is not optional left out, a Needs repair without a note, an answer that is not `ok`, `repair` or `na`, an item answered twice, or one not on the checklist (unknown or removed). Nothing is saved then. 405 for other methods. The Driver comes from the body until sign-in (ADR 0006) |
| `GET inspections/:id` | `{ inspection }` as `POST inspections` answers it; 404 if it does not exist. An Inspection is never changed or deleted: `PATCH`, `PUT` and `DELETE` are 405 (ADR 0006) |
| `GET check-ins?date=2026-11-19` | `{ date, checkIns: [{ driverId, driverName, truckId, truckNumber, inspectionId, doneAt, needsRepair }] }`: each Driver's latest Inspection that day (newest `doneAt`, ties by the order they were saved), in the Drivers' order; a Driver not checked in is left out, and two Drivers on one Truck are both listed. Any day can be read (only adding is limited to today). The Driver view reads today's for his check-in line; the Board reads today's for each lane while today is on screen. 400 `{ fields: { date } }` without a real date; 405 for anything but a read |
| `GET weeks/:monday` | The week strip: `{ days: [{ date, state, drafts, holiday }] }` for the seven days Monday to Sunday of the week starting on `:monday`. `drafts` counts the day's Drafts that are not cancelled, Unassigned ones included. `state` is `draft` while `drafts` is above 0 (the tile says "2 drafts"); otherwise `assigned` when it has Assigned Assignments and none is Changed or Added, `changed` when any is (a cancelled Assigned one counts as Changed), or `none` when it has none ("–"). `holiday` is the Holiday's name or null. Days before today are read too. 400 `{ fields: { date } }` for a date that is not a real Monday |
| `GET days/:date/start-from` | `{ from }`: the day Start from on `:date` would copy, the latest day before it with an Assignment that is not cancelled, or null when there is none. 400 `{ fields: { date } }` for a bad date |
| `POST days/:date/start-from` | Start from: copies the latest earlier day with Assignments (as `GET` names it) onto `:date` → 201 `{ from, to, assignments }`, `assignments` being the day as it now is. The copy takes only the columns it names, Driver, Truck, Places, Material and Foreman, so a column added later is never copied: each Assignment that is not cancelled is copied in the order the day is read, its note empty, created now, with a fresh `position` in its lane (0, 1, 2…); a removed (inactive) Place, Material, Truck or Foreman is left out, and an Assignment whose Driver was removed goes to Unassigned. Every copy is a Draft (`assignedAt` null), whatever its source was; Dave Assigns each. 400 `{ fields: { date } }` for a bad date or a day before today; 409 `{ error: 'day_planned', message }` when `:date` already has Assignments (cancelled ones count), and nothing is copied; 409 `{ error: 'nothing_to_copy', message }` when no earlier day has Assignments to copy; 405 for other methods |
| `POST days/:date/copy-to` | Copy to: JSON `{ to }` → 201 `{ from, to, assignments }`: copies `:date`, which must be a day before today, onto `to` (today or later; on the Board the next Working day) by the same rules as Start from. 400 `{ fields: { to } }` for a bad target day or one before today, `{ fields: { date } }` for a bad `:date` or one that is today or later; 409 `day_planned` when `to` already has Assignments; 409 `nothing_to_copy` when `:date` has none that are not cancelled; 405 for other methods |

Days before today (US Eastern) are read-only. Adding an Assignment on one is 400 `{ fields: { date } }`; Start from onto one is 400 `{ fields: { date } }` and Copy to onto one 400 `{ fields: { to } }`; changing, moving, Assigning, deleting, cancelling or putting back an Assignment already on one is 409 `{ error: 'past_day', message }`.

The Inspection checklist starts with the paper form's 12 items (ids `insp-01` to `insp-12`, `sortOrder` 1–12), loaded by `seed/inspection-items.sql` in every environment; re-running it only adds missing items, so a rename, reorder or removal stays.

Inspections are append-only, in the database too (an update to `inspections` or `inspection_answers` fails). `doneAt` is an ISO 8601 moment in UTC, shown in US Eastern; whether an Inspection needs repair is worked out from its answers.

The Worker reads the current time from its environment: `NOW` (an ISO 8601 moment) fixes it, as the tests do; deployed environments leave it unset. The old `orders` table is still in the database, unused.
