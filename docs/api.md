# API

The Worker's HTTP API, which the page uses. Shapes are typed in `shared/types.ts`; the day rules (Working days, Holidays, Changed and Added, day states) are in `shared/days.ts`. Words in capitals are defined in [`GLOSSARY.md`](../GLOSSARY.md).

Under `/api/` standalone or `/truck-dispatch/api/` under the Hub. No sign-in yet; Cloudflare Access protects previews and staging.

Every route that reads a body (including one whose fields are all optional, such as `POST truck-problems/:id/fix`) needs a JSON object: without a JSON `Content-Type` it is 415 `{ error: 'json_required' }`, and a body that is not a JSON object is 400 `{ error: 'invalid_json' }`. This is checked first, before a 404. Where several refusals are listed, they are checked in the order given unless a route says otherwise.

|---|---|

| `GET drivers`, `GET trucks`, `GET jobs`, `GET places`, `GET materials`, `GET foremen`, `GET inspection-items` | `{ drivers: [{ id, name, defaultTruckId, sortOrder, active }] }`, `{ trucks: [{ id, number, hcssCode, hcssGuid, active }] }`, `{ jobs: [{ id, name, jobNumber, active }] }`, `{ places: [{ id, shortName, fullName, kind, jobId, usualForemanId, geofenceCode, onTruckMap, sortOrder, active }] }`, `{ materials: [{ id, name, sortOrder, active }] }`, `{ foremen: [{ id, name, active }] }`, `{ "inspection-items": [{ id, label, optional, sortOrder, active }] }`. Only a job site has a `usualForemanId`; it is emptied when the Place stops being one, and an Assignment keeps its own Foreman, so changing it never rewrites a planned or past day |

| `PATCH <list>/:id` (drivers, trucks, jobs, places, materials, foremen, inspection-items) | JSON with only the fields to change, including `active: true/false` → 200 with the entry as for POST; 400 as for POST; 404 if it does not exist. | `PUT drivers/order`, `PUT places/order`, `PUT materials/order`, `PUT inspection-items/order` | JSON `{ order: [id, …] }`, the whole list first to last (removed entries may be included) → 200 `{ drivers }` / `{ places }` / `{ materials }` / `{ "inspection-items" }`, every entry including removed ones, in the new order. | `GET drivers/:id/later-days` | `{ laterDays }`: how many days after today (US Eastern) hold one of the Driver's Assignments, for the warning before he is removed. 404 if the Driver does not exist |
| `GET drivers/:id/next-assigned` | `{ date }`: the first day after tomorrow (US Eastern) that holds one of the Driver's Assigned Assignments that is not cancelled (his Drafts do not count), or null, for the Driver view's "Next from Dave". 404 if the Driver does not exist; 405 for anything but a read. (It was `next-sent`, now 404.) |
| `GET drivers/:id/days/:date` | The Driver view: one Driver's day → `{ date, assignments }`: only his Assigned Assignments (`assignedAt` set; his Drafts are left out, as Drivers see nothing of a Draft), as `GET assignments` gives them, cancelled ones included, in Dave's order. | `GET today` | `{ today, tomorrow, nextWorkingDay }`, dates in US Eastern time; `nextWorkingDay` is the first weekday after today that is not a Holiday (New Year's Day, Memorial Day, Independence Day, Labor Day, Thanksgiving, Christmas; a weekend Holiday is not moved) |
| `GET assignments?date=2026-11-20` | `{ assignments: [{ id, date, driverId, driverName, truckId, truckNumber, fromPlaceId, fromPlaceName, toPlaceId, toPlaceName, materialId, materialName, foremanId, foremanName, note, position, createdAt, updatedAt, changedAt, cancelledAt, assignedAt, handedFromId, sinceSent }] }`, Drafts and Assigned ones alike. `assignedAt` is when Dave Assigned it, null for a Draft; `handedFromId` is, on the copy made by giving an Assigned Assignment to another Driver, the id of the one it was handed over from, otherwise null; `cancelledAt` is when ✕ cancelled it (only an Assigned one is cancelled), null when it is not cancelled, and a cancelled one keeps its place; `sinceSent` is `'added'` for one Assigned on its own day (US Eastern) or handed over (`handedFromId` set), `'changed'` for one whose `changedAt` is after its `assignedAt`, otherwise null (always null on a Draft), also in the answers that add, change or Assign one; Place names are short names; `changedAt` is when it last really changed, null until then; a null `truckId` means "His own": the Driver takes his usual Truck. Listed by lane (in the Drivers' order as their list reads, no Driver last), then `position` (its place in the lane, from 0), then creation time. 400 `{ fields: { date } }` without a real date |
| `POST assignments` | JSON `{ date, driverId?, alsoDriverIds?, truckId?, fromPlaceId?, toPlaceId?, materialId?, foremanId?, note? }` → 201 `{ assignment, assignments }`, a Draft, last in its lane (its date and Driver, or Unassigned), or 400 `{ fields: { name: message } }` (bad date, unknown Driver, Truck, Place, Material or Foreman, note over 1000 characters). `alsoDriverIds` (a list of Driver ids) makes the same Assignment for each of those Drivers too, one each, last in his own lane: `assignments` holds them all, `driverId`'s first, which is also `assignment`. They are saved in one batch, all or none. 400 `{ fields: { alsoDriverIds } }` if it is not a list of ids, names a Driver twice (or `driverId` again), is sent without `driverId`, or names a Driver who is removed or does not exist. From and To may be the same Place. Unknown fields are ignored. Instead of an id, a Place or Material may be typed by name as `fromPlaceName`, `toPlaceName` or `materialName`: the entry with that name, ignoring case, is linked; a removed (inactive) one is made active again; otherwise a new one is added (a Place with no kind). This happens in the same request: if the Assignment is refused or not saved, nothing is added or brought back. 400 `{ fields }` on that name field for a blank name, one over 100 characters, or a name given together with the field's id |
| `PATCH assignments/:id` | JSON with only the fields to change, of `driverId`, `truckId`, `fromPlaceId`, `toPlaceId`, `materialId`, `foremanId`, `note`, and typed names as for POST: a field left out stays as it is, an empty one (null or `""`) is cleared → 200 `{ assignment }`. A real change of Driver puts it last in his lane (its date and Driver, or Unassigned); a real change sets `updatedAt` and `changedAt` to now and, once it is Assigned, keeps its fields as they were before (ids and names, note, position) in the add-only `assignment_changes` record; fields sent as they already are (the same Driver again, say) change nothing, not even those times. A Draft's change of Driver simply moves it. Once it is Assigned, a real change of Driver does not move it: it is cancelled (`cancelledAt` and `changedAt` now, its earlier fields kept) and a copy with the fields sent (the rest as they were, note included) is added last in the new lane, created now: given to a Driver, the copy is Assigned at once (`assignedAt` now, `handedFromId` the first one's id, so it is Added); given to Unassigned, it is a Draft → 200 `{ assignment: <the copy>, cancelled: <the first one> }`. A cancelled Assignment cannot be changed: 409 `{ error: 'cancelled', message }` until it is put back. The day is fixed: `date` may be sent only as it is; any other is 409 `{ error: 'day_fixed', message }`. 400 `{ fields }` as for POST; 404 if it does not exist. There is no PUT (405) |
| `POST assignments/:id/move` | JSON `{ direction }`, `"earlier"` (Do this first) or `"later"` (Do this later) → 200 `{ assignments }`: its lane (its date and Driver, or Unassigned) in its new order, swapped with its nearest neighbour that is not cancelled (cancelled ones keep their place and are stepped over) and numbered 0, 1, 2… again. Only the one moved gets `updatedAt` and `changedAt` (and, once it is Assigned, its earlier fields kept and the Changed mark); the neighbour that shifted does not. 409 `{ error: 'lane_end', message }` when no Assignment that is not cancelled is before it (earlier) or after it (later); 409 `past_day` on a day before today; 409 `cancelled` for a cancelled one; 400 `{ fields: { direction } }` for any other direction; 404 if it does not exist; 405 for other methods |
| `DELETE assignments/:id` | ✕. A Draft → 204, a real delete, nothing kept. An Assigned one is cancelled instead → 200 `{ assignment }` with `cancelledAt`, `changedAt` and `updatedAt` now, its earlier fields kept in `assignment_changes`; it stays in its place and the day. One already cancelled is answered as it is, except on a day before today. 409 `past_day` on a day before today; 404 if it does not exist |
| `POST assignments/:id/assign` | Assign: gives the Assignment to its Driver → 200 `{ assignment }` with `assignedAt` and `updatedAt` now (`sinceSent` `'added'` when Assigned on its own day, US Eastern). From then on its Driver sees it, and every change to it is kept and marks it Changed (ADR 0005). One already Assigned is answered as it is, keeping its first `assignedAt` (no Assign again, no lock). 409 `{ error: 'unassigned', message }` for one with no Driver (it stays a Draft until it has one); 409 `driver_removed` for one whose Driver was removed (no one would see it); 409 `cancelled` for a cancelled one; 409 `past_day` on a day before today; 404 if it does not exist; 405 for other methods. There is no Assign all |
| `POST assignments/:id/discard` | Discard: clears a cancelled Assignment off the Board → 204. From then on `GET assignments`, the week and the lane a move answers leave it out, and it no longer makes a day count as planned for Start from and Copy to. The Driver view is unchanged. Allowed on any day, past ones too; again is a no-op. 409 `{ error: 'not_cancelled', message }` for one not cancelled; 404 if it does not exist; 405 for other methods |
| `POST assignments/:id/dismiss` | Dismiss: the Driver clears a cancelled Assignment off his day → 204. From then on `GET drivers/:id/days/:date` leaves it out; the Board is unchanged. Same rules and refusals as discard |
| `POST assignments/:id/put-back` | Put back: clears `cancelledAt` (and any discard or dismiss) → 200 `{ assignment }`, with `changedAt` and `updatedAt` now and its earlier fields kept (so it is Changed). One not cancelled is answered as it is, nothing changed. 409 `past_day` on a day before today; 404 if it does not exist; 405 for other methods |
| `POST days/:date/send` | Gone: 410 `{ error: 'gone', message }` to any method. Each Assignment is Assigned on its own instead (`POST assignments/:id/assign`; ADR 0005). Days Sent before were carried over: every Assignment with a Driver on such a day, and every cancelled one, was Assigned when the day was first Sent (or when it was made, if later); the rest stayed Drafts, so a cancelled Assignment is never a Draft. | `POST inspections` | Check in: JSON `{ id, date?, driverId, truckId, answers: [{ itemId, answer, repairNote? }], otherNotes? }` → 201 `{ inspection }`, saved for today (US Eastern) with `doneAt` the Worker's clock now. `inspection` is `{ id, date, driverId, driverName, truckId, truckNumber, doneAt, otherNotes, needsRepair, answers: [{ position, itemId, label, answer, repairNote }], problems }`: the answers in the checklist's order (`position` from 0), each with the item's wording as it was (`label`), `answer` `ok`, `repair` or `na`, `repairNote` only on `repair`; `needsRepair` is true when any answer is `repair`; `problems` lists the Truck problems it opened (one per `repair` answer, in the answers' order, as `GET truck-problems` gives them), saved in the same batch as the Inspection, so a refused Inspection opens none. | `POST fleet-imports` | Import a Fleet export: JSON `{ fileName, format, rows }` → 201 `{ import }`. The Fleet imports page reads the dropped file into `rows` (`shared/fleetExport.ts`); the Worker never parses files. An xlsx export names no Truck and gives no odometers, so its rows carry the HCSS code of the Truck Dave picked and null odometers. `format` is `json` or `xlsx`; each row is `{ equipmentCode, geofenceCode, enteredAt, exitedAt, entryOdometer, exitOdometer }`, times UTC ISO 8601, `exitedAt` null while the visit is open, odometers numbers or null. A new visit is stored; a stored visit that is open is closed by a row with an exit; a closed visit is never reopened or changed; an entry time with seconds replaces a stored one given only to the minute. The Import that adds, closes or makes a visit's entry more exact is recorded as the one that last changed it. `import` is `{ id, truckId, truckNumber, fileName, format, importedAt, added, closed, unchanged, days, codesWithNoPlace }`: `importedAt` the Worker's clock now; `added` how many visits were new, `closed` how many open visits it closed, `unchanged` how many it held that were stored already ("already stored"; a more exact entry time counts here), all three also kept on the Import; `days` each US Eastern date its visits were entered on (a visit is filed under the Eastern date it entered, whatever its UTC date), in date order, as `{ date, added, closed, unchanged }` counting that day's visits the same way (they add up to the Import's counts; the dates are also stored as the days the Import covered); `codesWithNoPlace` every geofence code in the rows that no active Place has (matched ignoring case), sorted by code, as `{ code, driveThrough }`, `driveThrough` true when every visit there was closed and under 2 minutes (the Trip builder's drive-through), e.g. `{ code: "sunset", driveThrough: true }`. Days before today (US Eastern) are read-only. Adding an Assignment on one is 400 `{ fields: { date } }`; Start from onto one is 400 `{ fields: { date } }` and Copy to onto one 400 `{ fields: { to } }`; changing, moving, Assigning, deleting, cancelling or putting back an Assignment already on one is 409 `{ error: 'past_day', message }`.

The Inspection checklist starts with the paper form's 12 items (ids `insp-01` to `insp-12`, `sortOrder` 1–12), loaded by `seed/inspection-items.sql` in every environment; re-running it only adds missing items, so a rename, reorder or removal stays.

Inspections are append-only: the Worker never changes or deletes one (or its answers), and the database refuses an update to `inspections` or `inspection_answers` (a trigger). The database does not block a delete, since the tests clear the tables between tests; nothing in the Worker deletes them. `doneAt` is an ISO 8601 moment in UTC, shown in US Eastern; whether an Inspection needs repair is worked out from its answers. Truck problems are kept forever (`truck_problems`); only `fixed_at` and `fixed_note` are ever set, once. Their reporting Driver is nullable in the schema, so Dave adding problems later needs no table rebuild, but the Worker requires one for now.

The Worker reads the current time from its environment: `NOW` (an ISO 8601 moment) fixes it, as the tests do; deployed environments leave it unset. The old `orders` table is still in the database, unused.
